# セキュリティモデル

ランクパーティは遊び用コインだけを扱う身内向けアプリです。サーバーコードは持たず、Firebase Anonymous Auth と Realtime Database Security Rules（`firebase.rules.json`）で権限を表現しています。このドキュメントは、何を守り、何を守らないかを明確にするためのものです。

## 守るもの

| 脅威 | 対策 |
| --- | --- |
| 部外者がルームを覗く・荒らす | ルームを読めるのは幹事とメンバーだけ。メンバー登録は `roomMembers/{roomId}/{uid}` に**正しい参加コード**を書いたときだけルールが許可する。ルームIDは12文字、参加コードは16文字（32種の文字、約80ビット）を Web Crypto で生成 |
| 招待情報の漏えい | 招待リンクは資格情報を URL の**フラグメント（#以降）**に入れ、サーバーやリファラに送られない。読み込み後はアドレスバーから消す。`<meta name="referrer" content="no-referrer">` |
| 参加者が残高を増やす | 参加者が作れるのは `players/{自分のuid}` の1件のみで、残高はルームの初期残高と一致する必要がある。作成後の更新は不可 |
| 参加者が後出しベット・複数ベット | ベットは `currentRace/bets/{自分のuid}` の1件のみ、`status === "betting"` の間だけ作成できる。締切前に限り自分のベットを取り消して選び直せる（変更はできない）。幹事が締め切ると以降の書き込みは拒否される |
| 参加者が倍率を改ざん | ベットに `multiplier` を含めることをルールが拒否。精算時の倍率は幹事側で毎回計算し直し、保存された値は使わない |
| 不正な形・巨大なデータ | 型・長さ・許可フィールドをルールで検証（未知のフィールドは拒否）。金額は 1〜10億 の整数 |
| 同時書き込みによるデータ消失 | 幹事の通常の変更は、変更したパスだけを `update()` する（`src/lib/patch.ts`。参加者はフィールド単位）。締切・再開・精算・次のレース・ポイント付与はトランザクションで実行し、サーバー上の現在の状態が想定と異なれば中止する |
| 必ず当たる券種 | 対戦者が3人以下の複勝など、外れようがないチケットは精算時に無効（返金）とする。対戦者を減らしたときも該当するチケットを取り消す |
| 締切後の条件変更 | 締切後はオッズ、オッズの自動計算、借金ベット、人気によるオッズ変動を変更できない |
| 除外した参加者のアクセス | 幹事が参加者を外すと、そのメンバー登録も削除し、ルームを読めなくする |
| 外部スクリプトの注入 | Content Security Policy で `script-src 'self'`、`object-src 'none'`、`frame-src 'none'`、接続先は Firebase のみ。React の自動エスケープを前提に `dangerouslySetInnerHTML` は使わない |
| 旧形式ルームの悪用 | `schemaVersion: 2` 以外のルームはルールで読み書き不可（短い参加コードの旧ルームを封印） |

これらはエミュレータ上のテスト（`tests/firebase-rules.test.ts`）で確認しています。

## 守らないもの（既知の制約）

- **幹事は信頼される前提**です。幹事はルーム全体を書き換えられるため、残高や結果を任意に変更できます。お金や景品が絡む用途、敵対的な参加者がいる用途には向きません。その場合は Cloud Functions などのサーバー側で精算と監査ログを持つ必要があります。
- **匿名認証は端末ごとの簡易IDです。** ブラウザのデータを消したり別の端末を使ったりすると、幹事権限や参加情報は復元できません。
- **端末上のデータ**: デモと Firebase 未設定時のルームは localStorage に保存されます。オンラインルームの内容は端末に保存しません。最近のルーム一覧には参加コードや残高を含めません。共有端末では Firebase の匿名ログイン状態も残る点に注意してください。
- **オフライン時の変更**: 接続が切れている間の変更は Firebase SDK がメモリ上に保持し、再接続時に送信します。その間にアプリを閉じると失われます。締切・精算などの進行操作はオフラインでは実行できません。
- **参加人数の上限**: 上限はクライアントで確認しており、Security Rules では検証していません。
- **再参加**: 外された参加者でも、参加コードを知っていれば再び参加できます（初期ポイントから開始）。参加コードを変える機能はありません。
- **乱用対策**: Firebase App Check、利用量アラート、バックアップは Firebase プロジェクト側で設定してください。

## リリース手順

クライアントとルールは同じ PR でテストし、対で公開します。どちらを先に出すかは変更内容によって決まります。

1. CI（`validate.yml`）がすべて通っていることを確認する。
2. **ルールを先に公開してよいか確認する。** 新ルールが旧クライアントの書き込みも受け付けるならルールが先、受け付けないならクライアントが先。
   - 今回のリリースは**ルールが先**。ルールの変更は「参加者レコードの任意項目 `joinedAt`」と「締切前に自分のベットを削除できる」の2点で、どちらも旧クライアントの書き込みはそのまま受け付ける。新クライアントは `joinedAt` を書くため、旧ルールのままだと参加と代行参加者の追加が拒否される。
3. Firebase Console またはCLIで `firebase.rules.json` を反映する。
4. `main` に merge し、GitHub Pages のデプロイ完了を確認する。
5. 実機で、ルーム作成 → QR招待で参加 → ベット → 締切 → 精算 → 次のレース を確認する。予期しない拒否が出たらロールバックする。
